# Курьерская доставка «последней мили» — учебная практика

Тема №37, РТУ МИРЭА, осень 2026. Основа — система заказа и доставки еды
`food-delivery` (курсовая по АКСП, тема 19). **Исходный проект не
изменяется**: здесь лежит только новое, а исходный код используется как
есть — его сервисы, миграции, compose-файл и сквозные проверки.

## Что сделано на практике

Сервис доставки `delivery` (TypeScript/NestJS) переписан дважды с тем же
внешним контрактом — те же HTTP API, база `delivery_db`, события в Kafka,
канал позиции в Redis. Любая версия встаёт на место оригинала, остальные
сервисы замены не замечают.

| Папка | Что | Этап |
|---|---|---|
| `delivery-py/` | процедурная версия на Python: модули с функциями над словарями, классов нет | 3 |
| `delivery-py/delivery/lastmile/` | планирование «последней мили»: граф и Дейкстра, распределение заказов, ближайший сосед, 2-opt | 3 |
| `delivery-java/` | объектно-ориентированная версия на Java: иерархия курьеров, стратегии маршрута | 4 |
| `data/` | тестовый набор: улицы центра Москвы, 6 курьеров, 20 заказов; генератор | 3 |
| `docs/` | алгоритмы и сложность, BPMN «как есть / как будет», модель данных | 3 |
| `db/` | физическая модель «последней мили» (миграция 007) и её проверка на чистой базе | 5 |
| `docs/testing.md` | тестовые сценарии, покрытие, качество кода, журнал найденных ошибок | 5 |
| `compose/`, `scripts/` | отдельный стенд и подмена сервиса в docker-compose проекта | 3–5 |

Пакетная доставка (несколько заказов в одну поездку, требование DLV-7) и
собственный расчёт маршрутов в курсовой были сознательно вынесены за рамки
MVP — планировщик `lastmile` закрывает именно этот пробел.

## Быстрый старт

```bash
cd delivery-py
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt     # на Linux/macOS: .venv/bin/pip
.venv/Scripts/python -m pytest                        # модульные тесты
.venv/Scripts/python -m delivery.lastmile ../data/moscow_sample.json
```

Физическая модель и качество кода (этап 5, подробно — `docs/testing.md`):

```bash
cd delivery-py
.venv/Scripts/python -X utf8 ../db/check_migration.py   # миграция 007 на отдельной базе стенда
.venv/Scripts/ruff check . ../db                        # стиль и типичные ошибки
.venv/Scripts/python -X utf8 -m pytest --cov=delivery   # тесты с покрытием по модулям
```

`db/check_migration.py` подключается к PostgreSQL стенда (`localhost:25432`),
создаёт отдельную базу `delivery_lastmile_check`, применяет исходные миграции
delivery и затем `db/migrations/007_last_mile.sql` дважды, проверяет
ограничения и удаляет базу (`--keep` — оставить). Рабочие базы стенда не
затрагиваются; без сервера тесты миграции пропускаются.

Сквозная проверка сервиса на живых процессах (нужны Docker, Node.js и
собранный исходный проект в `../food-delivery`):

```bash
scripts/stand.sh up python    # инфраструктура fdlm + catalog, order, payment и delivery на Python
scripts/stand.sh e2e          # infra/verification/delivery-e2e.mjs исходного проекта
scripts/stand.sh down         # остановить процессы; destroy — удалить и контейнеры
```

Вся система в Docker с Python-версией вместо TS:

```bash
docker build -t food-delivery/delivery-py:local delivery-py
docker compose -f ../food-delivery/infra/compose/docker-compose.yml \
  -f compose/delivery-py.override.yml --profile apps up -d
```
